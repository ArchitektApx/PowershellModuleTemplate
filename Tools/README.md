# Developer tools

Everything here is meant to be run from the **repo root**. Every tool has a short name in
`tasks.ps1`, which is the intended entry point:

```powershell
./tasks.ps1 prepare                    # once, right after cloning the template
./tasks.ps1 cleanup                    # once, after prepare and hardening are done
./tasks.ps1 install_dev_requirements   # once per host, per PowerShell edition
./tasks.ps1 build                      # Source/ -> Dist/
./tasks.ps1 test
./tasks.ps1 lint
./tasks.ps1 coverage
./tasks.ps1 prepare_release 1.1.0
```

| Tool | Task | What it does |
|---|---|---|
| `prepare.ps1` | `prepare [-Platform <name>]` | One-time template setup: renames the manifest/root module, stamps the manifest, `build.psd1` and `LICENSE` from `module.psd1`, generates `PSScriptAnalyzer.psd1` and the CI matrix from the target-platform preset, renders `README.md` and `CHANGELOG.md`, removes the template-only scaffolding, installs the dev requirements. |
| `cleanup.ps1` | `cleanup` | One-time teardown of the setup machinery: deletes `prepare.ps1` and itself, and strips `prepare`/`cleanup` out of `tasks.ps1`. Run it once the repo is prepared and hardened. Keeps `module.psd1` and `Docs/HARDENING.md`. |
| `install_dev_requirements.ps1` | `install_dev_requirements` | Installs ModuleBuilder, Configuration, Pester 5+, PSScriptAnalyzer, plus anything in `module.psd1`'s `ModuleRequiredModules`, for the current user. |
| `build.ps1` | `build` | Clears `Dist/` and builds the module with ModuleBuilder. |
| `tests.ps1` | `test` | Runs the Pester suite against the built module. Throws on any failure, and on an empty run. |
| `lint.ps1` | `lint` | PSScriptAnalyzer over `Source/`: style/correctness, then WinPS 5.1 + pwsh 7 compatibility. Any finding fails. |
| `coverage.ps1` | `coverage` | Test run with code coverage, listing every missed command. `-MinimumPercent` gates the run. |
| `prepare_release.ps1` | `prepare_release <x.y.z>` | Runs the gates, promotes the changelog, stamps the version, rebuilds, and verifies the built manifest. |
| `get_changelog_section.ps1` | - | Extracts one section from `CHANGELOG.md`. Shared by `prepare_release` and the release workflow. |
| `module_info.ps1` | - | Resolves the module's name and paths from `build.psd1`. Dot-sourced by the other tools and by `Tests/_TestHelpers.ps1` so no module name is ever hardcoded. |
| `PSScriptAnalyzer.psd1` | - | Compatibility ruleset used by `lint.ps1`'s second pass. Generated by `prepare` from the platform preset. |
| `platforms/` | - | Target-platform presets. Deleted once `prepare` has run. |
| `templates/` | - | Skeletons rendered by `prepare.ps1`. Deleted once `prepare` has run. |

Every tool imports the **built** module from `Dist/`, the same artifact a user installs, so
`build` has to run before `test` or `coverage`.

## Notes

**Nothing hardcodes the module name.** `module_info.ps1` reads it out of `build.psd1`, which is
the same file ModuleBuilder reads. Renaming the module is therefore a `prepare` concern only.

**Coverage is per host.** Anything that runs in a child process reads as uncovered everywhere,
because the instrumentation cannot follow it. Compare hosts before concluding that a line is
untested.

**`prepare` is destructive by design.** It overwrites `README.md`, `CHANGELOG.md`,
`Tools/PSScriptAnalyzer.psd1` and `.github/workflows/ci.yml`, and deletes `res/`,
`Tools/templates/` and `Tools/platforms/`. Run it on a fresh clone, before you have written
anything.

## Target platforms

`ModuleTargetPlatform` in `module.psd1` picks one of the presets in `platforms/`:

| Preset | Manifest | Lint targets | CI hosts |
|---|---|---|---|
| `PowerShell5.1` | `Desktop`, 5.1.0 | 5.1 | win / WinPS 5.1 |
| `PowerShell7` | `Core`, 7.0.0 | 7.0 | win, linux, macos / pwsh 7 |
| `PowerShell5.1And7` | `Core, Desktop`, 5.1.0 | 5.1 + 7.0 | all four |

`prepare` uses it to set `CompatiblePSEditions` and `PowerShellVersion` in the manifest, and to
generate `PSScriptAnalyzer.psd1` and the `ci.yml` matrix. Override for a single run with
`./tasks.ps1 prepare -Platform PowerShell7`, and pin a higher minimum with
`ModuleRequiredPowershellVersion` (e.g. `'7.4.0'` on top of `PowerShell7`).

The choice is real, not cosmetic: a ternary or `??` in `Source/` lints clean under
`PowerShell7` and fails under `PowerShell5.1And7`.

**Retargeting after `prepare`** is a manual edit of two files, since `platforms/` is gone by
then: the `TargetVersions`/`TargetProfiles` in `PSScriptAnalyzer.psd1`, and the `include:`
matrix in `.github/workflows/ci.yml`. Keep `CompatiblePSEditions` in the manifest in step.

PSScriptAnalyzer ships no macOS 7.0 command profile, so the Linux one covers the whole
non-Windows side. The macOS CI row still runs the real suite there.
